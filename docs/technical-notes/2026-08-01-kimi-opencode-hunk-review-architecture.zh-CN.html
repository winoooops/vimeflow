Hunk Review · Multi-Agent Architecture

Kimi / OpenCode
Hunk Review 支持方案 复用中心协议，保留 provider-specific completed turn

这份文档解释 Vimeflow 的 hunk view 如何把用户 comments、delegated code review、agent structured reply 与 transcript recovery 串成同一条链路；并给出先 Kimi、后 OpenCode 的两个 PR 方案。重点不是再造一个 BaseAdapter，而是识别仓库里已经存在的中心接口。

PR 1 · Kimi PR 2 · OpenCode No new dependency No new IPC Shared schema Provider-local turn boundary

00 · Architecture Decision

结论：选择中心接口，但不新建 BaseAdapter

共享的是协议和输出；各 agent 只负责把自己的 transcript 还原成“一个完整 assistant turn”。

Rejected

每个 agent 复制完整流程

  • 各自解析 nonce、sentinel、JSON schema。
  • 各自定义 comments/review 输出类型。
  • 实时捕获和 recovery 再各复制一次。

结果是四套协议实现。状态 literal、malformed degrade、last-block 选择任何一处修复都可能漏掉其他 adapter。

Selected

复用现有窄接口

  • adapter 输出完整 assistant text。
  • 共享模块完成 schema 校验与 event mapping。
  • 同一个 adapter 实现 live 与 nonce-scoped recovery。

这是现有架构已经提供的路径：扩展 TranscriptStreamer，不向过渡期 AgentAdapter façade 增加新职责。

一句话规则：agent adapter 只回答“什么时候获得了一轮完整的 assistant 文本”；共享层回答“这段文本是不是 Vimeflow reply/review，以及如何变成统一事件”。

01 · Product Scope

这里其实有两种用户流程

UI 都在 hunk view 里，但协议、pending store 和返回事件并不相同。

Flow A · Comments

用户对某个 hunk 留言，再派发给主 agent

  1. 用户创建 question / bug / change / suggestion。
  2. Vimeflow 生成 nonce 和 VIMEFLOW_REPLY contract。
  3. 主 agent 回答、修复、拒绝或要求澄清。
  4. AgentReplyEvent 回到原 thread。

这是 comments section 的 structured Q&A / outcome 路径。

Flow B · Delegated Review

用户请求主 agent 对 file/changelist 做 code review

  1. Vimeflow 固化 diff placement snapshot。
  2. 请求主 agent delegate review。
  3. reviewer 返回 VIMEFLOW_REVIEW findings。
  4. AgentReviewEvent 把 findings 锚定到 hunk。

这是 code review section 的 reviewer finding 路径。

两条流程的共同输入是“完整 assistant turn + correlation nonce”，共同输出是稳定的 Vimeflow event；不同之处只在 reply/review schema 和前端落点。

04 · Boundary Design

什么统一，什么不统一

统一过多会把 provider 细节泄漏进 base；统一过少会复制协议和 bug。

Centralize

必须只有一个 owner

  • sentinel block 选择规则。
  • nonce 与 schema 校验。
  • reply outcome literal 映射。
  • review finding scope/category 校验。
  • malformed degrade 行为。
  • normalized event shape。
  • frontend capability 元数据。

Keep Provider-Local

每个 adapter 自己最了解

  • 哪一种 transcript row 是 assistant text。
  • 一轮回答何时结束。
  • streaming chunk 如何拼接和清理。
  • sub-agent output 是否属于主会话。
  • replay/live 分界。
  • 如何有限扫描 provider 原生 transcript。

不增加新的 completed-turn trait：目前没有跨 adapter 的 runtime caller 需要调用“给我完整 turn”。完整 turn 只是各 transcript decoder 内部通往共享 parser 的一个值。为了四个不同 wire format 造 trait，只会增加 pass-through 层。

可以抽取一个很小的共享 helper：review.rs 当前取第一个 review block，而 reply.rs 已采用“最后一个完整 block 胜出”。两者已经出现行为漂移，适合共享同一个 sentinel block selector；这不是 speculative abstraction，而是修复已存在的重复协议实现。超出 24 KiB 的 payload 不做 partial JSON parse，产生的 nonce-less diagnostic event 不能立即关联。 frontend 复用 pending record 的 dispatchedAt：30 分钟仍无合法结构化结果时， 在原 feedback handle 或 review-level surface 写入可操作失败说明并清除持久化 pending， reload 不会无限 recovery。

06 · Provider Path

Kimi：streamed parts 组成 completed turn

Kimi 的差异集中在“如何得到完整文本”，一旦得到文本，reply/review 的解析不再是 Kimi-specific。

01 · START

turn.prompt

只接受 origin.kind == user；新用户 turn 清空旧 buffer。

02 · FILTER

Main wire only

sub-agent wire 不参与主回复，避免把 delegated worker 文本误当结果。

03 · BUFFER

content.part

只拼接 part.type == text；think block 被排除。

04 · BOUND

Tail clamp 32 KiB

保留 turn 尾部；共享协议按原始 UTF-8 byte range 计数：从 open marker 行的换行后开始，到 close marker 行首结束，payload 行自己的 LF/CRLF 计入，marker 行的缩进、blockquote prefix 与尾空格不计入；但每个原始 marker line 自身最多 256 bytes，超限不识别。payload 上限为 24 KiB，且每轮最多一个 reply 或 review block，确保完整 合规 block 留在 buffer 内。

05 · COMPLETE

step.end/end_turn

take buffer，一次调用 reply parser 与 review parser，然后清空。

最小复用：把 buffer append、UTF-8-safe tail clamp、fresh-user-turn clear、end_turn take 封装成 Kimi adapter 内部的小型纯状态对象。live decoder 和 recovery scanner 共用它，并保留 retained first byte 是否原始 line boundary 的 boolean； partial first line 中的 inline marker 不会因 clamp 变成 standalone marker。

Kimi 必须保持的行为不变量
  • finishReason == tool_use 不能 flush。
  • 只有 main wire 的 end_turn 能结束主回答。
  • think part 中即使包含 sentinel 也不能 emit。
  • 被中断 turn 的 buffer 不能泄漏到下一轮。
  • recovery 的每个 tail window 必须先看到真实 main-agent user prompt；窗口开头残留的 content/end 记录一律忽略。
  • 首次 replay 继续推进既有状态，但不能重复产生 live reply/review event；其他 lifecycle/activity/summary 行为不变。
  • recovery 可以扫描历史 turn，但只返回请求 nonce。
  • 超过 32 KiB 的违规 block 只保证内存有界，不从残片 emit。

OpenCode Plugin

Assistant snapshots in memory

boundary 本身不视为换行；若最终 tail 从已 clamp 的 active segment 起步，必须使用 active 保存的 provenance，不能借用 committed 的最后一个换行。 这里依赖 OpenCode 原生的 同 part snapshots 连续 contract，不为不可能的 A→B→A 保存 seen-ID set。 active snapshot 入库前先做 UTF-8 byte clamp。unknown-role pending LRU 合计使用 64 KiB / 256 messages， pending accumulator 与 confirmed assistant 使用相同的 part-ID full-snapshot replace、next-part commit 与 provenance 规则，promote committed tail 与独立 32 KiB active snapshot；active snapshot 变短时直接替换，最终再合并 clamp，因此不需要找回已丢弃的 committed bytes。 它不会被 user/unresolved text 污染。role 先到时写入 bounded knownRoles，后续 parts 直接按 assistant/user 路由；同 role 重复更新幂等， role 冲突则该 message fail closed。idle 只输出 current assistant。 如果因 pending/message 上限而 ignored 的 ID 后来确认是 assistant，必须先清掉 旧 current candidate 并继续忽略新 ID，idle 不得误发已被 supersede 的旧回复。 text part 以 08 · Recovery Model

为什么 live capture 还不够

用户切 pane、刷新 renderer、恢复 workspace 或在 watcher replay 窗口中错过事件时，pending comment/review 仍必须找回结果。

DISPATCH

Frontend 持久化 pending nonce

comments 存在 pending review store；delegated review 存在 pending request store，并记录 owner、PTY 与 diff snapshot。

PERSIST

Agent transcript 保存 completed turn

Kimi 保存 wire events；OpenCode bridge 保存 assistant.text。

REATTACH

UI 按 PTY 查询仍 pending 的 nonce

调用现有 recover_agent_replies / recover_agent_reviews IPC，不需要新增 command。

SCAN

Provider adapter bounded scan

复用 for_each_bounded_line，忽略 malformed/oversized rows；provider 按 transcript 顺序交出完整 turn，base recovery collector 负责 requested nonce 与原始顺序； 每个 Kimi adapter 保存 newest 256 个成功 tail 的 original main-wire paths；同一个 original path 取最后一次，指向同一 canonical target 的不同 aliases 继续保留；scan 前重新校验并按新的 canonical identity 分组， 对 original path 做 no-follow open；每个 path 扫描 128 KiB 尾部（总计最多 32 MiB），并只 保留 newest 512 completed turns，再按承载 step.end 的顶层 record.time 排序。 frontend 负责内容相同的 reply 幂等，初始 review 每 nonce 只恢复首个。

INGEST

同一套 frontend handler 幂等消费

recovered event 与 live event 使用同一条 nonce gate 和 thread placement 路径。

安全/资源边界不变：IPC 已限制 nonce 数量与长度；transcript path 已由各 adapter 校验在 provider root 下；只有新旧 streamer 声明相同的 provider + canonical validator trust root，base 才继承历史路径。跨 provider、root 变化或默认未声明 domain 都 fail closed，只保留新 adapter 已验证的路径。扫描使用共享 bounded-line reader。recovery IPC 在 clone source 前获取同一 session gate，确保新 tailer 的 replay summary 不能抢在 source publication 前 扫描旧 source；clone 后立即释放 gate，不跨文件 I/O 持锁。scan 后再用 source revision/generation/domain 检查，replacement/teardown 期间得到的旧 result 直接丢弃。永久删除 PTY 每次 PTY spawn 分配单调 generation。PtyState 用一个短生命周期 mutex 一次性 snapshot generation/cwd/shell PID/start time，并串行化 session insert 与成功 remove 后的 agent-generation close/cache/event；remove 后先 close generation，再发布 cache/event， callback 在 lifecycle gate 内、sessions mutex 外 detach 并 signal watcher/transcript， A 完成关闭后才允许同 ID 的 B 插入；callback 返回 handles，gate 外再 drop/join。 BackendState 构造时给 PtyState 注册 唯一 generation-removal callback；reader/reaper 调用 remove primitive 时 带上捕获的 expected generation，仅匹配当前 entry 才实际删除并同步发 (session ID, generation) teardown，因此旧 generation 的延迟 EOF/read error 不能删掉同 ID 的新 PTY；只有实际移除匹配 generation 后才能更新 cache 或 emit pty-exit/pty-error。它先在 PTY mutex 内 extract，再释放 mutex 后进入 agent gate，即使上层后续 cache update 失败也不遗漏。gate 内 close generation 并移除匹配 agent state；watcher 注册和 transcript publication 也必须在同一 gate 下拒绝 closed generation，因此没有有效 transcript hint 的旧 attach 也不能发布。每次 attach 分配独立 attach-instance identity：同一 attach 的重复 callback 可判定 AlreadyRunning， 同 PTY 内的新 agent process 必须 replacement。gate 外 join。reader 的 generation mismatch 是完整 no-op；用户 explicit close 即使 EOF 已移除 PTY， 仍在 lifecycle gate 下删除 exited cache entry，避免下次启动恢复旧 session。 explicit close 在 lifecycle gate 内锁定 expected generation 后才 kill/remove； child.kill() 失败时则保留 PTY/cache/generation/agent state 供重试。 kill 成功后若 cache mutation closure 失败，PTY/agent 仍保持已移除并返回错误； list reconciliation 把旧 row 标为 exited，第二次 close 重试删除。disk flush failure 沿用现有 best-effort：内存已删、记录日志并返回成功。 agent watcher/tailer 使用 attach-scoped GenerationEventSink；每次 emit 在同一 agent gate 下检查 captured (generation, attach-instance ID)，A closed 或被同 PTY 新 attach 替代后的迟到 status/reply/review 会被丢弃，terminal event 仍走原 sink。这里的 agent gate 就是唯一的 TranscriptState session gate；replacement 在 gate 内只 detach/signal 并设置 token 与 one-shot installation latch，所有 wait/join/provider I/O 都在 gate 外； recovery 和新 tail worker 等待 Installed/Aborted，再凭 token 安装或丢弃。 新 installation latch 只交给 recovery waiter 与 candidate tailer；incumbent sink 看到 Replacing 后直接按旧 identity/revision 丢 event，绝不等待 candidate latch， 因而 replacement 可以先 join incumbent 再决定 Installed/Aborted，不形成环形等待。 watcher startup 改为 prepare → under-gate commit watcher + attach ID → activate； 所有可失败 setup 在 commit 前完成，initial decode/tail 只在 commit 后运行。 同 generation 已有更大的 process-monotonic attach ID 时，较旧或相等 ID 的 prepared watcher 在 gate 内直接丢弃，不能覆盖较新的 commit。 这里“丢弃”只表示 gate 内标 stale、关闭现有 owns_transcript cascade 并 detach； watcher/transcript handle 必须返回 caller，在 gate 外 drop/join。旧 watcher 即使在新 same-session attach commit 后才析构，也不能再通过 Drop 调用按 session ID 的 stop 去移除新 transcript；被拒绝的 prepared watcher 同样在 gate 外清理。 Kimi/OpenCode tail() 的这项兼容改动都在 PR 1：先返回 handle，initial cwd 由 worker emit，避免同步等待自己的 latch；OpenCode review parsing 仍在 PR 2。 PR 1 也冻结 OpenCode locator root 并返回 non-None RecoveryDomain，保证同 attach 的重复 callback 可走 AlreadyRunning；这不包含 OpenCode reply/review parsing 或 capability。 watcher commit 对新的 attach-instance 一律 fail-closed：gate 内 detach/signal 旧 watcher/transcript、清空 recovery history，gate 外 join；只有同一 attach 内的 path replacement 才能按相同 non-None domain 继承历史。

11 · Verification

测试架构：共享基本面，provider 证明原生文本

测试边界与生产边界保持一致：共享层证明协议和 recovery 生命周期；每个 adapter 只证明自己的 transcript 如何产生完整 reviewer text。不要把同一套前端行为复制四遍。

01 · PROTOCOL

Shared parser

sentinel 选择、JSON schema、malformed 降级、finding 校验；与 provider 无关，只测一次。

02 · RUNTIME

Base recovery

source 保存、stop 后可恢复、forget、error forwarding 与 bounded line scan；同 provider/root 才继承 history，跨 provider/root replacement 必须清空旧路径。

03 · PROVIDER

Native transcript contract

Claude assistant、Codex task_complete、Kimi parts、OpenCode assistant.text 各自还原 reviewer text。

04 · FRONTEND

Normalized ingestion

provider 消失后只测 nonce、owner、thread/hunk 落点；agent capability 另做薄测试。

最小中心接口：生产代码继续使用现有 TranscriptStreamer::recover_replies/recover_reviews 与共享 extract_agent_reply/extract_agent_review。测试中不再造 “universal completed turn” trait 或四-provider 宏；各 transcript envelope 差异太大，provider-local builder + 一张一致性 checklist 更直接。

每个 provider 的最小一致性契约

契约 共同断言 Provider 自己决定的部分
Live completed turn 普通 reviewer prose + VIMEFLOW_REVIEW 只产生一个 AgentReviewEvent；断言 sessionId、nonce、reviewer、finding text/scope。 什么 row/字段代表 assistant text 与 completion。
Not completed / wrong source 不产生 live review。 Claude tool_use、Codex 非 task_complete、Kimi think/sub-agent/tool_use、 OpenCode 非 assistant.text。
Replay 历史 transcript 不重新 emit live review。 各 decoder 自己的 caught-up / replay_done 边界。
Recovery reply 保留全局最新 128 个 requested matches 并按原序返回； review 每 nonce 只返回首个 completed match；unrelated/incomplete 忽略；sessionId 使用调用方 PTY。 如何从历史 rows 重建 completed reviewer text。
No sentinel 普通文本不产生 reply/review。 只需 provider 的最小合法 native row。

两个 PR 的具体测试增量

PR 1 · Foundation + Kimi

  1. Shared parser：standalone/block-quoted marker、JSON text marker literal、last complete、trailing orphan 与 24 KiB limit。
  2. Base TranscriptState：reply + review delegation/lifecycle；两种 recovery error forwarding。
  3. Kimi live：split text review 在 main end_turn emit；think、sub-agent、tool_use 不 emit；replay 不 emit。
  4. Kimi recovery：A→B→C wire history 全扫；reply 断言 same-nonce 顺序，review 断言每 nonce 首个；validator/NotFound skip 与 fatal read error 分开测试。
  5. Frontend：picker 根据 supportsHunkReview，不再根据 label；Kimi true、OpenCode false、Shell false。

PR 2 · OpenCode

  1. OpenCode live：assistant.text review emit/no-emit；replay review 不 emit。
  2. OpenCode recovery：同一 bridge JSONL 放 requested same-nonce turns、unrelated 与非 assistant.text row； reply 保序返回，review 每 nonce 只取首个。
  3. 同时锁住 reply recovery，防止实现 review 时只接半条协议。
  4. Registry/picker：只把 OpenCode capability 从 false 翻 true；Shell 仍 false。
  5. 增加 plugin v4 安装与 astral-character prefix 测试，证明 clamp 不产生 unpaired surrogate 或无效 JSONL；超过 256 个顺序 text parts 拼出的完整 24 KiB block 仍被保留；同 part snapshot 只替换不 重复；非连续旧 part 更新 fail closed；oversized active snapshot、 multi-message 与 message 257 在 idle 前遵守 session-wide byte/message caps；session.error 不得把失败 turn 泄漏到下一次 idle；backend 启动、 PTY 创建前安装 v4，失败则本次运行无 OpenCode live candidate，attach retry 只准备下一次 backend run；assistant.text 写入 startsAtLineBoundary，旧 v1 row 缺字段按 false；record schema version 仍为 v1。
刻意不复制哪些测试？
  • 不给四个 agent 各复制 finding schema、malformed JSON、last-block tests；这些属于 shared parser。
  • 不给四个 agent 各复制 frontend nonce/owner/hunk-placement tests；normalized event 进入 UI 后 provider 已经不可见。
  • 不建立一套 provider conformance macro；四个 native envelope 不同，宏只会隐藏测试 输入，降低 reviewer 可读性。
  • 不为 OpenCode 做 breaking schema-version 变化或数据库迁移；只修复 producer 的 Unicode-safe byte clamp，并给 assistant.text 增加向后兼容的可选 provenance 字段。

12 · Risks & Invariants

实现时不能简化掉的边界

这些不是未来扩展；它们直接防止错 thread、重复 finding、内存放大和 transcript 越界读取。

Correlation

Nonce 必须匹配 pending request

未请求或已 superseded 的 nonce 不能进入当前 hunk review state。

Completion

只能解析完整 assistant turn

不能扫描用户 prompt，也不能在 streaming 中间看到半个 sentinel 就 emit。

Bounds

内存与行长度必须有限

Kimi 保持 32 KiB tail；recovery 使用 bounded-line reader。

Path Security

只扫描已验证 transcript

session gate 内先 stop/join 旧 tailer，再 snapshot 默认空的 recovery_paths()；所有来源必须已经 validated/canonicalized，merge 只按 exact original path 去重并保留 newest 256，不能提前丢掉同一 canonical target 的不同 aliases。只有相同的非空 RecoveryDomain（agent type + canonical validator trust root）才继承旧 history；跨 provider、root 变化或默认 None 都清空旧路径，且 domain 是 start_or_replace identity 的一部分。recovery clone source 前获取同一 session gate；每次 open registration 从 validator 起就同时传递 original provider path 与 canonical identity；live tail 使用 canonical path，恢复保留 original 做 revalidate + no-follow open，避免 start_or_replace 丢失任一语义。恢复时 validator 用 original path 校验 canonical containment；任何 validation error 都只跳过该 candidate。成功项按新 canonical identity 分组，不先丢 aliases；每组从 newest original path 开始调用 filesystem 的 leaf open_nofollow，NotFound/Symlink 则试下一个 alias， 首个可读 alias 只扫描一次。group ordinal 固定取 newest member 的原始位置， fallback 不改变 timestamp tie order；其他 I/O 可 propagate。它拒绝删除、已有越界路径与 leaf symlink，但不 虚假宣称解决同用户反复替换 parent component 的竞态；后者需要全仓 fd-relative traversal。任何情况下都不能接受 renderer 任意路径。

Replay

历史扫描不等于 live emit

live decoder 的 replay gate 与显式 recovery 是两条不同意图的路径。

Capability

只有完整链路才能标 true

只有 parser 而无 recovery 或 UI reachability 时，不能宣称支持 hunk review。

不要做：新增 provider-specific event、把 provider name 塞进 frontend routing、让 OpenCode PR 修改 bridge schema、把 recovery 路径改成 renderer 提供文件路径、或为了四个 adapter 新建一套 factory/interface 层。
